# Testing

## Layers
- **Unit** (`tests/unit`, `npm test`): pure domain and library code, no DOM, no I/O, fixed `now` and `newId`. Node's built-in runner (`node --test`) with native TypeScript stripping; no test framework. Needs Node 24 (`.nvmrc`): a Node 22 built without TypeScript support (some distro builds) fails with `ERR_NO_TYPESCRIPT`.
- **Golden** (`tests/golden/*.json`, generated by `scripts/golden-from-proto.mjs`, `npm run golden`): the frozen prototype engine (`witt-grace-gpt-proto/src/core.js`, callable from Node) is run over every example in `witt-grace-gpt-proto/examples/*.witt.json` and over hand-built cases (the G-02 table, four-level propagation, sign reversals, missing and stale reviews, groups, gates, values, two-context reuse, secondary routes, shares weighting, ballot rounds). Each fixture records the input document and, per node, viewpoint and weighting, the internal `I`, the visible `S`, completeness, eligibility and ballot results. The new engine must reproduce every value exactly. Fixtures are regenerated only by that script and committed; a diff in a fixture is a spec change.
- **Prototype regression** (`npm run proto:check`): the prototype's 372 tests, kept green because the prototype is the oracle.
- **Parity** (`tests/unit/*-parity.test.ts`, `tests/unit/ai-*.test.ts`, `tests/unit/lib-*.test.ts`, run by `npm test`): the frozen prototype module (`createRequire` of `witt-grace-gpt-proto/src/*.js`) and its port are driven with the same input — every example, every orientation, every key, every filter — and the outputs are compared literally (positions, paths, rows, prompts, documents, SVG bytes). A port that "looks right" but differs by one constant fails here.
- **Browser** (`tests/e2e`, `npm run e2e`, Playwright, Chromium only, from WG-009): walks through the pages a person sees, driven by the prototype's element ids so the same steps work in both apps, literal Finnish oracles, desktop 1440×900 and mobile 390×844 projects. The app starts on the home screen like the prototype (`tests/e2e/helpers.ts`). `tests/e2e/parity-walk.spec.ts` runs one walk against the prototype (served at 4174 by the second `webServer` entry) and against the app (4173) and asserts the collected texts are equal (WG-025). When several Playwright runs may overlap, pass `--output <private dir>`; Playwright empties `test-results/` at start. `tests/e2e/session-walk.spec.ts` (WG-030) drives two and three browser contexts against each other over the local relay `scripts/signal-relay.mjs` (the third `webServer` entry, 127.0.0.1:8787); its contexts bypass the page CSP because the built page allows `wss:` only, and Chromium runs with `--disable-features=WebRtcHideLocalIpsWithMdns` so loopback candidates connect.
- **Collaboration without WebRTC** (`tests/unit/session-flow.test.ts`, `store-collab.test.ts`): the host and participant controllers run in Node over `LoopbackHub`, whose delivery is manual (`flush`), so a test can lose, delay or reorder messages. Host keys and tokens come from WebCrypto; no assertion depends on their values.
- **Docs** (`npm run check`): local links resolve, every spec is listed in `docs/spec/README.md`, no lens carries an unfilled placeholder, a spec change carries a changelog line.

## Requirement pairing
Every test file header carries `must:` (the behaviour), `test:` (where) and `red-against:` (the realistic mistake the test catches: an inverted sign, a dropped clamp, a missing review treated as zero, an author relabelled — never "delete the function"). Where a requirement has an ID in `docs/spec/REQUIREMENTS.md`, the header names it (`G-05`, `UX-C05`). The PR template repeats the pairs; `/verify` checks that changed test files have the header.

## Oracles
Assert literals: `I` and `S` to the stored precision, `null` for missing, eligibility words, author IDs, JSON bytes after canonical serialization, message text. `assert.ok(result)` is not an oracle. Error paths assert the specific message or refusal reason.

## Clocks and identity
Never read the wall clock or `crypto.randomUUID` in a test. Unit tests pass `now = '2026-11-08T10:00:00.000Z'` and a counting `newId` (`id-1`, `id-2`, …); golden fixtures carry their IDs inside the document.

## Mutation probe
Before trusting a test, break the implementation the way `red-against` describes and watch it fail; `/feature` does this before the commit (`git stash push -- src && npm test; git stash pop`). Log of probes:
- 2026-11-08 WG-003: the purity test was seen red against its own first draft (a prose "document." in a comment), then narrowed to code-shaped patterns; the golden suite went green on the first run of the ported engine, so no engine mutant has been probed yet — the first scoring probes (clamp dropped, null read as 0, AI pooled) are due with WG-004.

- 2026-11-11 WG-030: `authorizeCommand` returning allow for another person's review → `session-protocol.test.ts` red; the participant applying commits without checking `seq` → `session-flow.test.ts` red only after the duplicate-commit assertion was added (the digest check healed the first version of the test silently).

## Manual walks pending
- None yet. Every UI milestone adds a side-by-side walk against `/proto/` at both widths; the owner looks at what no assertion sees (layout, contrast, the feel of the focus ring, the Bitberg lanes).

## Flake rules
No sleeps, no network, no real clock in unit or golden tests. Browser tests run one worker, bounded waits only, and never assert on timing. CI prints the failing test's output; a flaky test is fixed or deleted, never retried.
