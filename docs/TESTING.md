# Testing

## Layers
- **Unit** (`tests/unit`, `npm test`, from WG-003): pure domain and library code, no DOM, no I/O, fixed `now` and `newId`. Node's built-in runner (`node --test`), no test framework.
- **Golden** (`tests/golden/*.json`, generated by `scripts/golden-from-proto.mjs`, WG-002): the frozen prototype engine (`witt-grace-gpt-proto/src/core.js`, callable from Node) is run over every example in `witt-grace-gpt-proto/examples/*.witt.json` and over hand-built cases (the G-02 table, four-level propagation, sign reversals, missing and stale reviews, groups, gates, values, two-context reuse, secondary routes, shares weighting, ballot rounds). Each fixture records the input document and, per node, viewpoint and weighting, the internal `I`, the visible `S`, completeness, eligibility and ballot results. The new engine must reproduce every value exactly. Fixtures are regenerated only by that script and committed; a diff in a fixture is a spec change.
- **Prototype regression** (`npm run proto:check`): the prototype's 372 tests, kept green because the prototype is the oracle.
- **Browser** (`tests/e2e`, `npm run e2e`, Playwright, Chromium only, from WG-009): keyboard-first walks through the pages a person sees, named by role and label, literal Finnish oracles, screenshots at 1440×900 and 390×844 compared against the prototype side by side.
- **Docs** (`npm run check`): local links resolve, every spec is listed in `docs/spec/README.md`, no lens carries an unfilled placeholder, a spec change carries a changelog line.

## Requirement pairing
Every test file header carries `must:` (the behaviour), `test:` (where) and `red-against:` (the realistic mistake the test catches: an inverted sign, a dropped clamp, a missing review treated as zero, an author relabelled — never "delete the function"). Where a requirement has an ID in `docs/spec/REQUIREMENTS.md`, the header names it (`G-05`, `UX-C05`). The PR template repeats the pairs; `/verify` checks that changed test files have the header.

## Oracles
Assert literals: `I` and `S` to the stored precision, `null` for missing, eligibility words, author IDs, JSON bytes after canonical serialization, message text. `assert.ok(result)` is not an oracle. Error paths assert the specific message or refusal reason.

## Clocks and identity
Never read the wall clock or `crypto.randomUUID` in a test. Unit tests pass `now = '2026-11-08T10:00:00.000Z'` and a counting `newId` (`id-1`, `id-2`, …); golden fixtures carry their IDs inside the document.

## Mutation probe
Before trusting a test, break the implementation the way `red-against` describes and watch it fail; `/feature` does this before the commit (`git stash push -- src && npm test; git stash pop`). Log of probes:
- 2026-11-08: none yet; the first probes are due with WG-003.

## Manual walks pending
- None yet. Every UI milestone adds a side-by-side walk against `/proto/` at both widths; the owner looks at what no assertion sees (layout, contrast, the feel of the focus ring, the Bitberg lanes).

## Flake rules
No sleeps, no network, no real clock in unit or golden tests. Browser tests run one worker, bounded waits only, and never assert on timing. CI prints the failing test's output; a flaky test is fixed or deleted, never retried.
