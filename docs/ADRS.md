# Architecture decision records (ADR)

Started 2026-11-08. One table, one row per decision; the prototype handoff's "ADR" mentions are history. Rows marked *(proposed)* wait for the owner's confirmation; *(open)* rows name the options and the trigger for deciding. A new runtime dependency or a reversed boundary needs a row here (CLAUDE.md).

| ADR | Decision | Why | When to re-open |
| --- | --- | --- | --- |
| A001 | Rebuild from scratch; the dev32 prototype is frozen in `witt-grace-gpt-proto/`, runnable, published at `/proto/`, and used as the scoring, format and UX oracle (owner decision 2026-11-08; supersedes the handoff's in-place refactor roadmap) | The prototype's UI is good and its engine is tested, but its code (a 4 333-line DOM monolith, tests that grep source text) is not a foundation; a rebuild under golden fixtures keeps the behaviour and replaces the structure | Never for the oracle role; the prototype is deleted only after the new app passes every golden fixture and every UX item in `docs/spec/REQUIREMENTS.md` |
| A002 | TypeScript strict on Node 24 LTS (22.18+ works) with native type stripping for domain, scripts and tests (`erasableSyntaxOnly`, `verbatimModuleSyntax`, `noUncheckedIndexedAccess`, relative `.ts` imports); `node --test`; ESLint 9 + typescript-eslint + Prettier; the UI alone is built by Vite (A005). Accepted 2026-11-08 under the owner's "make the choices" mandate. Note: a Node 22 built without TypeScript support fails with `ERR_NO_TYPESCRIPT`; Node 24 is the floor in practice | One runtime for tests, scripts and tooling; the owner's other project proved the setup; the domain stays runnable without a build | A non-erasable TypeScript feature becomes necessary; the UI choice (A005) brings its own toolchain |
| A003 | Dependency direction `src/domain` (pure, builtins only) ← `src/lib` ← `src/app`, enforced by ESLint and an import-direction test; closed sets owned by one module each; parse once at the boundary | The prototype's audit named exactly this as the missing boundary; it is what makes the golden fixtures runnable without a browser | Never casually; a cycle or a reversed arrow is an ADR |
| A004 | Document format `schemaVersion: 8` and scoring `evidence-v3-links` preserved exactly; the prototype's `schemas/project.v8.schema.json` is copied and asserted equal; golden fixtures generated from the prototype engine are the numeric contract | People's existing `.witt.json` files keep working; the method's numbers are the product | A deliberate v9 or a new scoring identifier, each with a migration function, before/after fixtures and a `docs/spec/CHANGELOG.md` line |
| A005 | UI: **React 19 + TypeScript + Vite**, plain CSS with custom properties for themes (no Tailwind, no CSS-in-JS), no global state library: the document lives in one store (`useSyncExternalStore`) fed by serializable domain commands; components render view models computed by `src/domain`. Browser tests with Playwright against roles, accessible names and `data-testid`s so an agent can drive the UI. Accepted 2026-11-08 by the owner's mandate (rejected: vanilla DOM — the prototype showed where that ends; Preact — smaller, but React is what the owner's other product uses and what tooling and models know best; Svelte/Solid — fine frameworks, no advantage for a tree editor that outweighs ecosystem familiarity) | A long-lived UI with docking, dialogs, a large SVG tree and later live P2P state needs a component model; React's escaping-by-default serves invariant 5; serializable commands are the P2P event log in waiting | The single-file offline export proves impossible with Vite (then a post-build inliner); React's bundle makes the Pages load noticeably slow on mobile (then Preact via the compat alias) |
| A006 | Static hosting on GitHub Pages from `main` by workflow: the prototype under `/proto/`, the new app under `/`; one-file offline standalone kept as a download | Local-first, no backend; the prototype is reachable in a browser as the owner asked | A custom domain for private use (storage-origin isolation, `docs/spec/SECURITY_AND_PRIVACY.md`) |
| A007 | Spec lock (owner request 2026-11-08): `docs/spec/**` changes only with a line in `docs/spec/CHANGELOG.md` in the same change; a Claude hook refuses the edit otherwise and CI refuses the PR; requirement IDs are permanent; numbers are pinned by tests | Specs must not drift by accident while the code is rebuilt; the mechanism is one hook and one 40-line script, not a process | If the hook produces false refusals in practice (then the rule moves to CI only) |
| A008 | Language: English code, docs and commits; Finnish-first UI with nine locales from one catalog and a coverage test that fails on a missing or raw key; the prototype's vocabulary is the glossary | The owner reads Finnish UI with ä/ö; the nine locales exist and must not rot | A tenth language; a vocabulary change (then the glossary in `docs/ARCHITECTURE.md` changes first) |
| A009 | Browser tests with `@playwright/test`, Chromium only, keyboard first, from WG-007 on (the first UI slice ships with its walk); every interactive element has a role, an accessible name and, where the name is user text, a `data-testid`; the prototype's Python smokes stay with the prototype | The owner asked for a UI an agent can test by machine; rendering, focus order and the dock cannot be asserted from Node; Chromium is what the prototype was verified on | Safari or Firefox parity becomes a requirement |
