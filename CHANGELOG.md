# Changelog

All notable changes to this project. Format: [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Versions are 0.x: a minor may contain breaking changes. "Reviewed:" lines record quality-review rounds.

## [Unreleased]

### Added
- Owner request 2026-11-11 (WG-030): one collaboration never has the same name twice. A general join with a name already in the document, the session or a live invite is refused and asks for another name (instead of “Name (2)”); the invite form refuses a new name in use and points to the list; the host refuses a participant's rename to a name in use. Nine languages.
- Owner request 2026-11-11 (WG-030, third part): a clearer invite dialog. *Kutsu mukaan* asks who (anyone, with the general link, or a named person) and how the invite is protected (*Linkki kiinnittyy yhteen selaimeen* / *Linkki ja erillinen salasana*, each with its help); a made invite shows its link and password whole, together, with their own copy buttons; *Vaihda salasana* gives a password invite a new password with the same link (the admitted seats stay); choosing a person who already has a link says what a new one does. Connection fixes: a TURN server per browser under *Lisäasetukset: yhteydet*, eight public Nostr relays instead of five, a 45 s wait, and a join that fails tells an absent host from one found without a direct connection and offers *Yritä uudelleen*; nine languages.
- Owner decisions 2026-11-11 (WG-030, second part): a personal invite's browser always comes back with the same link; an optional password mode for personal invites (any browser, one at a time; suggested four-word Finnish passwords or your own; PBKDF2 proof bound to the host key; five wrong tries lock, the host unlocks); *Uusi kutsulinkki* replaces a person's link; every link names its own door, so a personal link never yields the general one; the host's reload continues the same collaboration and participants reconnect.
- Owner request 2026-11-11 (WG-030): live collaboration without cloud storage. *Tiedosto → Kutsu muita mukaan…* or *Työskentele yhdessä* on the home screen starts a session from the open document or a new blank one; a general link asks the joiner's name first, a personal single-use link carries a name the joiner cannot change (an existing profile or a new one). The host orders every change; participants edit the tree and give their own assessments, comments and ballots, governance stays with the host. The document travels only between browsers (WebRTC via Trystero, ADR A010); signaling through public Nostr relays or the owner's own relay (`scripts/signal-relay.mjs`), swappable behind one adapter. Undo is off during a session; when it ends everyone keeps a copy. Nine languages, user guides, RFC §15, security and inventory updated; the CSP allows `wss:`.
- Owner request 2026-11-11: in the assessment round a ⋮ button next to the parent context lists every ancestor up to the root, each marked supporting, opposing, option or root, so the whole chain of claims is visible. Nine languages.
- Owner request 2026-11-10: a compact assessment round: the guidance texts and questions sit behind a ? button, spacing is tighter, and the buttons stay in view at the bottom (the dialog fits a 680 px high window). Nine languages.
- Owner request 2026-11-10: *Painota viivat ja perustelut arvioiden mukaan* (on by default, in the layers panel): an edge's width and opacity follow the weight its reason actually carries under the document's method, and a nearly weightless reason fades, so four weak counter-reasons no longer look decisive. Nine languages.
- Owner requests 2026-11-10: *Arvioijien arviot, mediaani* as a way to pool reviews (one extreme assessor no longer decides), and a fifth calculation method *Vahva ketju välittyy (log-odds, kokeellinen)* (`chain-logodds-v1`): one fully credible ±5 reason reaches ±95, so a strong chain carries up from deep down. Nine languages; `tests/unit/median-chain.test.ts`.
- Owner request 2026-11-10: the child-count chip reads *2 / 16 alisolmua · alipuu* (direct children / the whole subtree) when the subtree is larger; nine languages.
- Owner request 2026-11-10: card text visibility. A title now uses the card's room (four lines instead of two); *Näytä kaikki tekstit (lukunäkymä)* in the view dock grows every card to its text and lays the tree out by size, with card width and line limit per browser (`src/app/reading.ts`); a selected card can be resized from its corner and keeps that size in the document (`layout.nodeSizes`, `node.resize`, double click restores). Nine languages; `tests/unit/cards.test.ts`, `tests/e2e/cards-walk.spec.ts`.
- Owner request 2026-11-10: *Korosta käyttäjän jäljet* in the view dock highlights the nodes one chosen person created, edited last or commented on (rings and a mark; other nodes fade), independent of the active profile, with a shortcut to that person's ratings. Nine languages; `tests/e2e/highlight-walk.spec.ts`.
- Owner request 2026-11-10: a fourth calculation method, *Nettotulos välittyy (kokeellinen)* (`signed-reasons-v1`): a reason passes its net result upward (strength = max(0, net / 100)), so a neutral or refuted reason adds nothing. Explained in the inspector and the quick guide (nine languages); the comparison examples' tables gain its column.
- Owner request 2026-11-10: a ninth example, *Syvä väittely: keskustan ruuhkat* (same script): counter-claims to counter-claims 14 and 11 levels deep with parallel claims, against two short options.
- Owner request 2026-11-10: an eighth example, *Laskentatapojen vertailu: tietokoneiden uusiminen* (`scripts/build-scoring-example.ts`, `--table` prints each option's net under every method): four options with long, deep and short sets of reasons for comparing the calculation methods.
- Owner decisions 2026-11-10: *Jätän tämän arvioimatta (muut voivat arvioida)*, a checkbox in Punnitse and the assessment round: the person abstains from a reason, and their ratings of it and of the branch below count nowhere (shared result, review lens, own view) and are not expected; the branch is dimmed in their view with a note; clearing the box brings the ratings back (new document field `abstentions`, command `review.abstain`). The wording separates it from *Ei arvioida – koskee kaikkia*. Nine languages.
- Owner decisions 2026-11-10: a reason can be an unrated note (*Ei arvioida*, `node.unrated`): no sliders, never scores, never leaves its parent incomplete, earlier reviews kept; a new neutral reason starts so, and the assessment round can mark one. An influence 0 needs no credence under v4 and log-odds. *Tarkka asteikko (0,1)* (`node.fineInfluence`) gives one relation 0.1 steps; the data accepts influence in 0.1 steps everywhere (the prototype's half steps remain valid). Labels in nine languages; `tests/unit/unrated-fine.test.ts`, `tests/e2e/unrated-walk.spec.ts`.
- Owner decisions 2026-11-09: a node can have its own type name (*Oma tyyppinimi*, e.g. Kriteeri, Tavoite, Kandidaatti) shown on the card instead of the built-in tag and passed on to the next sibling option or value; the `,` key adds a value judgment under the selected card (rebindable); two synthetic recruitment examples (one candidate against criteria, three candidates on the same criteria) generated by `scripts/build-recruitment-examples.ts`. New document field `typeLabel`; labels in nine languages (`UI_INVENTORY.md` S-15).
- G-02 in `GRACE_AND_DATA_MODEL.md`, the user guides and the in-app help (`helpImportance`, nine languages) explain the marginal effect Δ shown by *Korosta painavimmat*: what it answers, how it is computed, two worked examples, why only some cards show it. `tests/unit/marginal-effects.test.ts` pins the examples. WG-028 records the owner's question about an unrated note node and the impact wording.
- Owner decision 2026-11-09: three themes, per browser like the other skins: ▮ Terminaali (green phosphor terminal), # ASCII (cards and tree edges drawn from characters; `src/app/AsciiEdge.tsx`) and ✎ Sarjakuva (xkcd-like hand-drawn look with the bundled Comic Neue font, SIL OFL 1.1, `src/app/fonts/`). Their styles live in `src/app/themes-added.css`, after the untouched prototype stylesheet. Labels in nine languages (`UI_INVENTORY.md` S-15).

### Changed

The app was rebuilt against it: home screen; top bar with home and about; toolbar with the Kartoita/Punnitse/Päätösäänestys stages, the actor select with "+ Lisää paikallinen käyttäjä…", the five menus item for item and the perspective banner; left panel with outline, the `Yhteydet ja perustelut` pane and the add block; canvas cards with inline `+ − * ▦ ▾` buttons, author marks, chips per layer, the context menu, inline title editing, drag (also from the title), three orientations with the prototype's layout maths, compact and depth projections, branch focus, secondary-link edges with arrow markers, zoom/pan/fit, the quick bar in "Vain puu"; the `Näkymäasetukset` dock; the inspector section by section (library-reason inspector, concept and locked boxes, relation and parent selects, the "Arvioinnin mukaan" line, the Punnitse hint, own sliders, comparison, score hero with breakdown, advanced details with sources and overlap note, concept uses, legacy links, comments, options ranking); the assessment round, review lens, vote, people, help (with customisable shortcuts), links, examples, replace, library, visual export dialogs and the guided tutorial; the table presentation with the mobile list. The prototype's stylesheet is now `src/app/styles.css` (eight themes). `src/domain` gains `layout.ts`, `navigation.ts`, `lens.ts`, `table.ts` and `ai/` (ai-draft v2, contribution v2 and bundle v1, starter v1, import preflight), each a line-for-line port with parity tests that load the frozen prototype modules; `src/lib` gains `workspaceMeta.ts`, `library.ts` (IndexedDB) and `export/` (PNG/SVG/PDF). Browser walks start from the home screen and use the prototype's element ids.

### Changed

### Added
- WG-012: repeated reasons. A claim's inspector offers "Liitä myös muihin solmuihin…": a target picker (only targets the domain accepts) creates the concept and a new use under the target, selected and visible at once, with its own ratings. A use shows the concept box (manage in the shelf, detach keeping its ratings) and a badge on its card. The left panel's second tab is the shelf: create a card (`Luo kirjastoon`, a blank title becomes "Uusi perustelu"), see every concept with its uses and each use's own `75%/+5`, open a use's reviews, attach a card to the selected node. `canReuseClaimAt` joins the domain. `tests/e2e/reuse-walk.spec.ts` rates the same reason 70 %/+4 under one option and 90 %/−3 under another.
- WG-015 (table half): the argument table beside the tree — every claim in logical order with its direct relation, context, this person's credence and influence and the balance; search and relation filter; a tree/table switch in the toolbar. `index.html` carries a Content-Security-Policy (scripts and connections from the page's own origin only, no inline script, no framing).
- WG-011: decision mode in the app. The decision root's inspector shows the options overview (feasibility badge from gates, balance, ballot preference, ordered as the domain ranks them: feasibility, completeness, balance). The Arviointi menu opens the people dialog (names, vote shares, the pooled-weighting choice equal/shares/structural, switch, remove) and, in decision mode, the ballot dialog: weights frozen when a round opens, interim results hidden until the round closes, per-person 0–100 sliders with save and retract, the owner closes the round, closed rounds archive with their results. `tests/e2e/decision-walk.spec.ts` walks two options, a review, a second person and a full round.
- WG-007: the new app. React 19 + Vite + TypeScript (ADR A005): `src/app/store.ts` holds the document and dispatches serializable commands with undo/redo and autosave; the shell has the prototype's zones — top bar (title, `Alt+1..4` pane toggles, language, theme incl. Bitberg), toolbar (Argumentointi/Päätös, person, viewpoint, File/Edit/View/Help), outline, pannable and zoomable canvas with draggable cards, edges, balance and `75%/+5` pairs, inspector (title, details, relation, parent, semantic type, gate status, score explanation with contributions, personal review sliders, comments), bottom zone, `Alt+V` dock, footer with the prototype link. Keyboard: `+`/`−` add, `Del`, `F2`, `Ctrl/Cmd+Z`, canvas zoom and pan. JSON export and open with the replacement confirmation that names the current work. Playwright (`npm run e2e`): seven keyboard-first walks at desktop and mobile widths. CI gains a `browser` job; the Pages workflow publishes the app at `/` and the prototype at `/proto/`.
- WG-006: the nine-language catalog. `locales/messages.psv` is the prototype's table (866 keys); `npm run i18n` (`scripts/generate-locales.ts`) renders the typed `src/lib/i18n/catalog.ts` (`MessageKey`, `Language`); `src/lib/i18n/i18n.ts` gives `translate(language, key, params)` and a bound `translator`. Tests pin that the committed catalog equals the rendered table, that every key is non-empty and not raw in all nine languages, that `{placeholders}` agree across languages, and the Finnish glossary words.
- WG-005: `src/domain/serialize.ts` — the `.witt.json` file form (`JSON.stringify(validated, null, 2) + '\n'`), byte-identical to the prototype's export for every example and stable under a second round-trip; the compact storage form; the export filename slug (pinned to the prototype's NFKD quirk).
- WG-004: every document change is a serializable `Command` (43 types) applied by `applyCommand(project, command, { now, actorId })` in `src/domain/commands.ts`: pure, ids supplied by the caller so a peer can replay the same log, the input never mutated, refusals with the prototype's messages, `lastEditedBy` and `createdBy` tagged and the result re-validated like the prototype's mutation wrapper. `src/domain/project.ts` creates blank documents and tidy-tree layouts; `src/domain/views.ts` holds the view-only projections (visible nodes, focus highlighting that respects explicit collapses, option group path, guided review order, value profile, evidence-overlap note). `tests/unit/commands.test.ts` replays 60 edits through the prototype engine and through the commands with identical ids and clock and asserts identical documents after every step.
- WG-003: `src/domain` in TypeScript — the v8 model and closed sets (`model.ts`), the parser as the single trust boundary (`parse.ts`, the prototype's Finnish refusal messages kept), the `evidence-v3-links` engine for the collective viewpoints and per person (`scoring.ts`, with marginal effects), review readers (`reviews.ts`), feasibility (`eligibility.ts`), ballot preferences (`ballots.ts`) and rankings (`ranking.ts`). Pure by construction: no DOM, storage, clock or randomness; imports only inside the folder (ESLint and `tests/unit/import-direction.test.ts`). Tooling: TypeScript 5.9 strict with Node's native type stripping (Node 24; `.nvmrc`), ESLint 9 + typescript-eslint, Prettier, `node --test`. `npm run check` now runs docs, spec lock, lint, typecheck, format and tests.
